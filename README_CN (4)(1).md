# 引理 2.10 与 2.11 的穷举验证

本验证以用户提供的 `Li-Zhang(1).pdf`（37页）为对象，直接检验第8页两个引理的结论。

## 运行

仅使用 Python 标准库，无须安装 NetworkX、Sage 或 nauty。
代码使用 `int.bit_count()`，建议使用 Python 3.10 或更高版本。
本次实际运行环境见 `results/results.json`。

```bash
# 完整范围：引理2.10的11--16阶，以及引理2.11的11--18阶。
python verify_lemmas_210_211.py --out results

# 单独运行计数器交叉测试。
python verify_lemmas_210_211.py --self-test

# 完整交叉核对：小阶生成器、枚举覆盖性、最大值见证图。
python audit_verifier.py --results results

# 只验证至13阶；此命令不是完整范围的验证。
python verify_lemmas_210_211.py --max-n 13 --out small_results
```

Windows 系统可以将 `python` 换成适当的 `py` 命令；macOS/Linux 环境也可用 `python3`。

## 验证对象与范围

原文“最优路径”为从最远叶子到唯一圈的路径 `x0,x1,...,xd`，首先最大化到圈距离d，
再对 `(deg(x1),...,deg(xd))` 取字典序最大值（PDF第4页）。

* 引理2.10：11 <= n <= 16，d >= 4，前三项度数为(3,2,2)。
* 引理2.11：11 <= n <= 18，d >= 4，前两项度数为(3,2)，第三项大于2。

程序没有使用附录第22页的“每个支撑点至多邻接两个叶子”以及“支撑点不相邻”两个额外限制。
也没有使用归纳假设。因而它直接验证原文有限图类上的严格结论，强于仅在归纳假设下验证结论。

该计算是对引理结论的独立验证，不是对附录全部中间估计式、图示分类和变换论证的逐行审核。

## 为什么只需生成至14阶的核

在任意满足两个引理条件的图中，x0是最远叶子，x1的三个邻点为x0、x2及另一叶子y。
否则y若还接有其他顶点，就会出现比x0更远的顶点。又因为deg(x2)=2，
删去{x0,y,x1,x2}后得到一个(n-4)阶连通单圈图H，且x3不在圈上。

原图可从H恢复：在r=x3处添加r--x2--x1，并在x1处添加两个叶子x0,y。
引理2.10对应deg_H(r)=1；引理2.11对应deg_H(r)>=2。
所以，对全部H以及其相应类型的圈外顶点r进行此操作，必然覆盖两个引理中的每个图。
生成后再严格计算原图的最优路径，筛选并精确去同构。

引理2.10只需核的阶数7--12；引理2.11只需核的阶数7--14。

## 核生成与精确去同构

每阶加入该阶纯圈。其余连通单圈图都有叶子，删去一个叶子后仍是连通单圈图，
因此都可从前一阶的图添加一个叶子产生。这证明 `unicyclic_levels` 的生成完整性。

删除唯一圈的圈边后，每个圈顶点是一棵根树的根。根树使用括号编码：
叶子为 `()`；其他根树的编码为 `(` + 排序后的所有孩子编码 + `)`。
沿圈排列这些根树编码，再在全部旋转和反向中取字典序最小值。

根树编码由孩子根树的多重集唯一决定；单圈图同构必须把唯一圈映到唯一圈，
而圈上的同构恰为旋转或反向。因此两个规范编码相同当且仅当两个单圈图同构。
Python字典/集合在哈希冲突时仍比较完整键值，本程序不是用有碰撞风险的图哈希来判同构。

## 精确计数为何成立

顶点有三种状态：0为未选入D；1为选入D且在G[D]中孤立；2为选入D且在G[D]中度数为1。
一个状态赋值对应极大dissociation set，当且仅当每个顶点满足以下局部条件：

* 状态1：所有邻点为0。
* 状态2：恰有一个邻点为2，其余邻点为0。
* 状态0：至少有一个状态2的邻点，或者至少有两个已选邻点。

最后一条正是“该顶点不能加入D”。因此状态赋值与极大dissociation sets一一对应。
特别注意：计数对象是maximal，不是maximum。

`tree_summary` 对根树自底向上递推六个计数(T,A,B,I,P,M)：

* 根为0时，T是所有孩子的可行组合数；A是孩子全为0的组合数；B是恰有一个孩子为1、其余为0的组合数。
* 根为1时，I是孩子全为0的组合数。
* 根为2时，P是孩子全为0的组合数；M是恰有一个孩子为2、其余为0的组合数。

设父点状态为p，根状态为s，则消息表的非零候选项为：

```
p\s      0          1      2
0        T-A-B      I      M
1        T-A        0      0
2        T          0      P
```

根的极大性可以由其父点补足，但每棵子树内的后代条件均已检查。
圈顶点再用两个圈邻点的状态补足对应条件，由 `local_table` 生成局部权重W。
最终计算 sum(product(W_i(s_{i-1},s_i,s_{i+1})))，首尾指标按圈长取模。
`phi` 使用相邻状态对的动态规划完成这个求和，而不枚举全部2^n个顶点子集。

所有计数为Python整数；不存在数值取整或浮点累积误差。
在固定三状态模型中，单图计数的算术操作数为O(n)。

## h(n)的严格比较

原文第3页给出的函数在n>=5时为

    h(n) = 2 * 3^((n-2)/3) + n - 5.

指数不能向下取整。由于立方函数严格递增，精确等价式是

    Phi(G) < h(n)
      iff (Phi(G)-n+5)^3 < 8 * 3^(n-2).

PASS/FAIL全部采用右侧整数比较。CSV中的h_approx和gap_approx仅用于显示。

## 交叉核对

`audit.log` 记录了已经实际完成的如下检查：

1. 对全部3--9阶连通单圈图，共383个非同构图，独立枚举2^n个顶点子集，核对动态规划计数。
2. 对3--6阶，独立枚举所有具有n个顶点和n条边的标号图，筛选连通图后去同构，核对核生成器。
3. 对11--13阶，直接生成原阶全部单圈图并筛选两个引理条件，与“核加四顶点分支”的图数和最大值比较。
4. 对结果表14个参数组分别保存的一幅最大计数见证图，再以独立2^n子集枚举核对Phi及其结构条件。

所有检查通过。`audit_verifier.py` 可重现这些核对。

## 文件说明

- `verify_lemmas_210_211.py`：主程序，默认覆盖完整原文范围。
- `audit_verifier.py`：独立交叉核对脚本。
- `results/summary.csv`：各阶的核心图数、尝试根数、合格非同构图数、最大Phi、达到最大值的图数及通过情况。
- `results/results.json`：运行环境及逐阶记录。
- `results/witnesses.json`：每个参数组一幅最大计数见证图的邻接表、圈长、最优路径、规范编码及整数比较余量。
- `run.log`：主程序实际输出。
- `audit.log`：交叉核对实际输出。

见证图的顶点编号从0开始；前cycle_length个顶点按编号顺序构成唯一圈。
若发现违反严格不等式的图，程序会保存 `failure_*.json` 并以非零退出码结束。
